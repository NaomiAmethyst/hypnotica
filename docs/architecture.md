# Architecture

`cmd/hypnotica` is the executable entry point. `internal/site` owns the builder:

- `cli.go`: arguments, validation reporting, scaffolding, and preview HTTP.
- `config.go`, `scan.go`, `model.go`: configuration, YAML compatibility, discovery,
  normalization, and the catalogue/detail field boundary.
- `sanitise.go`: text-only HTML policy, applied when records enter the model.
- `media.go`: probing, copying/linking, declaration-based pruning, ID3 writing,
  and transcript fingerprints.
- `build.go`: build orchestration and catalogue/search/transcript serialization.
- `feed.go`: combined and per-author podcast RSS.
- `web.go`, `web/`: embedded browser assets and procedural icons.

The Go module path is intentionally local (`hypnotica`) until a public hosting
location is chosen. To change it, update go.mod and the entry point's import.

## Invariants

1. Source files are read-only. Retagging applies only to output copies.
2. Item IDs are global. A duplicate must never silently replace an item.
3. Resolve inputs from documents, not reconstructed directory conventions.
4. Media pruning uses declared claims, including unresolved declarations.
5. Preserve declared extensions when resolving symlinks.
6. Prefer declared transcript fingerprints; hashing a large library is costly.
7. Descriptions are sanitized once, before any downstream representation.
8. Keep detail-only fields out of the catalogue. Change DATA_SCHEMA when a
   serialized field changes meaning; update browser CATALOG_SCHEMA when its
   stored representation changes.
9. Saved audio has an unversioned cache. Rebuilding must not clear downloads.
10. An unchanged catalogue page should have an unchanged manifest hash.

## Dependencies

YAML uses the YAML organization's maintained Go package. Unicode normalization,
HTML tokenization, and BLAKE2b use Go's x packages. ID3v2 writing is isolated
behind `tagMP3`. TagLib is embedded as WebAssembly and executed by wazero for
format-aware audio properties; CGo and external executables are unnecessary.
Versions and checksums are locked in go.mod/go.sum. See THIRD_PARTY.md.

## Validation

Python-generated snapshots under `testdata/golden` independently pin parsed
JSON, feed semantics, and transcript outputs. They are not regenerated by tests.
Go tests cover normalization, legacy YAML scalars/merges, cache precedence,
pruning, copy/link transitions, audio formats, fingerprints, ID3 fields, rebuild
stability, CLI behavior, and real HTTP range requests. Browser suites use actual
embedded app code and generated files, with browser APIs stubbed by jsdom.

No test needs private libraries, credentials, network access, or Python after
Go and npm dependencies have been installed. See tests/README.md for limits.
